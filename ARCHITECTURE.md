# Upstream APIs are part of Charmed's contract

Status: accepted.

Charmed deliberately exposes Bubble Tea and the underlying component libraries. Bubble Tea messages, commands and lifecycle methods, concrete upstream models, options, styling types and chart data types may appear in public APIs. Consumers can use native capabilities directly; dependency independence is not a goal.

Thin constructors return native models where shared defaults are sufficient. Wrappers add Charmed behavior and composition while retaining native access. Do not introduce parallel message systems, generic widget interfaces or replacement data types solely to conceal an upstream dependency.

Charmed owns semantic themes, cell geometry, focus conventions, status meaning and composed behavior. Application services and business decisions stay outside the UI library. Pure analysis and policy packages such as `cohort` and `attention` remain independent of terminal rendering.

Exposed upstream types are part of our compatibility surface. Review dependency upgrades for changes to public types, methods, options and behavior, and document migration requirements when consumers are affected. Supporting a different terminal framework would require a separate design decision.

Native access carries lifecycle responsibilities. A wrapper may rebuild its underlying model during data updates or resize; direct mutations are not automatically persistent. Document what is retained or reset and how callers should apply customization. Preserve documented guarantees and verify them through the wrapper's public operations. Existing preservation gaps remain defects to address; this decision does not establish guarantees the implementation lacks.

Shared visual geometry is part of composition: controls reserve one horizontal cell on each side, and panels include those content gutters inside their declared allocation. Use `layout.PanelContentSize` or `chart.PanelPlotSize` when allocating native children. Theme constructors apply named glyphs and matching focus insets as defaults; concrete native styles and glyph setters remain available to callers. The guide exports completed static cells with exact RGB rather than emulating live terminal control sequences.

Disabled text presentation is applied to a native model copy: default prompt, dim text and cursor suppression are wrapper behavior; a caller's custom prompt and underlying styles remain intact. Native `Model` access can bypass those wrapper policies deliberately. Native chart options continue to override theme defaults; heatmap constructors copy the theme's sequential scale so native scale edits do not mutate the theme.

Command palettes expose native search and result models while retaining ownership of command items, filtering, delegate geometry and selection reconciliation. Resize preserves styles, key maps and input prompts; replacing commands preserves the selected ID when it remains matched. Applications execute selected command IDs through Bubble Tea messages. Overlay composition and dimming change rendered presentation, and do not pause application ingestion or replace underlying pane state.

Navigation presets are explicit configuration applied before native overrides; resize and data refresh never reapply them. Vim palette search and navigation modes separate printable input from movement. Backdrop dimming preserves categorical colors by blending toward the supplied theme background; monochrome and unchanged backdrops are separate display policies.

Inspector pane folding retains captured data and native child models. Hidden request, response and log viewports keep their size and scroll position until reopened; visible reflow can clamp offsets. Help and headline rows are measured before allocating content. Timeline height is content-driven. The inspector’s independently scrollable request and response columns use separate native viewports; logs move below the pair before the pair stacks at narrow widths. Payload customization belongs on `LogInspector.Request` and `Response`; `HTTP.Details` retains the standalone combined view. Shared `HTTPLog` content renderers keep capture, formatting and parameter semantics consistent. `layout.Section` owns presentation only; the inspector owns fold state and geometry. `layout.IdentityHeader` escapes identifier data and wraps the complete value rather than abbreviating it.

JSONViewer composes a native viewport pointer with an ordered document of retained source ranges. Structure never passes through a decoded map or floating-point representation. The viewer owns projected content and structural selection; native styles and bindings survive refresh. The inspector binds RequestJSON and ResponseJSON to its existing Request and Response models and retains source-bound snapshots per observation and direction. Snapshots contain no payload bytes and are evicted with observations. Complete declared JSON must pass capture, encoding, byte, depth, node and rendered-output limits before structural interaction becomes available. Raw/formatted offsets are independent; changing body bytes resets structure, while resizing and presentation changes retain it. Native line paging remains available for wrapped scalar values.

Declared layout nodes describe cell allocation rather than replacing component models. `layout.Resolve` produces an immutable plan of named rectangles, explicit omissions and accepted design exceptions. `tui.Screen` requires complete region coverage, exact visible-view inputs and strict design validation. Applications resize and update native models themselves; hidden panes keep their native state. Failed arrangement invalidates screen rendering until a new allocation succeeds.

A screen owns one reusable native canvas for its current allocation. Immediate Render reads every supplied child view; RenderRetained instead accepts explicit region revisions and lazy rendering callbacks. It retains fitted output only for visible regions, revalidates clipping diagnostics and recomposes when allocation or revisions change. Callers must advance revisions after native customization, scrolling, focus or data changes. Callers serialize screen arrangement and rendering within their model lifecycle. Returned frame strings remain independent of later renders. Static workbench fixtures retain only their current allocation's source rendering; interactive component models and their exposed native customization are never hidden behind that fixture cache.

Compiled layout declarations own validated copies of every branch; resolving new geometry still enforces allocation and design rules. PrepareMarkdown retains parsed and highlighted source independently of wrapping width, with one current rendered result. Native chart resizing preserves the underlying model instead of reconstructing it. Geometry-only ResizeViewport methods skip presentation refresh on height changes; existing Resize methods retain their refresh contracts. LogInspector.ViewRetained accepts independent request, detail and log revisions while its immediate View remains uncached.

Design exceptions are local to a rule and region or named container, with a nonempty reason. They remain observable in diagnostics and cannot relax geometry invariants. Responsive validation requires caller-supplied size cases covering every declared branch; it does not prove arbitrary text inside a region is well designed. Existing free-form string composition stays useful below the screen boundary.

ScrollPane binds an existing native viewport pointer and owns its content, dimensions and offset clamping; native styles, wrapping and key bindings survive updates. GridInspector coordinates stable grid selection with details and requires Refresh after direct grid mutations. KeyedTable owns native rows and selection reconciliation, validating a full replacement before mutation. PatchBrowser copies complete patch observations and retains file-and-section identity; applications still own Git access. MeasurementHistory copies validated cohort data and keeps missing observations distinct from unavailable ratios. TraceReplay copies a supplied graph and trace, identifies repeated transitions by occurrence and performs no execution or clock effects.

The pure `catalog` package owns reusable component identities, typed composition and specialization relationships, and separately identified consumer and interactive examples. Relationships retain roles and source declarations; atomic levels remain declared classification rather than inferred depth. `story.ComponentGraph` supplies an explicitly partial audited slice. Existing `Definition.Composes` remains legacy catalog metadata, and is not promoted into verified component relationships automatically. Guide publication resolves evidence against Go declarations, derives both navigation directions and exports the same validated data as versioned JSON.
