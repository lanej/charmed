# Correlated HTTP and application logs

The log inspector is built from HTTP method/status atoms, a structured log-tree molecule, and an HTTP-log molecule. `pattern.NewLogInspector` coordinates these components without collecting data or issuing network requests. Run `go run ./cmd/workbench run pattern/log-inspector` for the combined native fixture, or run `collection/log-tree` and `collection/http-log` separately.

Supply `collection.HTTPExchange` observations and `collection.LogRecord` values wrapping the existing `LogEntry`. Each record needs a unique nonempty ID; request, trace, span and parent-span IDs are explicit optional correlation metadata. Use `SetEntries` to replace a dataset and `UpsertRequests` / `UpsertLogs` to deliver changes through the owning Bubble Tea update loop. Do not mutate UI models from producer goroutines. Failed dataset validation leaves the current dataset intact.

Requests initially follow the latest arrival. Navigating older records pauses follow; `F` resumes it for the focused request or log pane. Upserts replace existing IDs in place and append new IDs in arrival order rather than reordering by timestamp. Retention defaults to `collection.DefaultLogLimit` (500 records); the inspector's `Limit` option applies to each collection. Eviction repairs a removed selection using the first retained record. Nested `LogEntry.Fields` values remain caller-owned immutable observations; do not mutate nested maps or slices after submitting them. HTTP header values and captured body bytes are copied on input and output.

Exact request-ID matching is the default correlation scope. `t` switches to exact trace-ID matching when the selected request has a trace ID. Missing identifiers are shown as unavailable; an available identifier without matches is shown as no matching logs. Neither timestamps nor message text establish relationships. The tree supports grouped traces and spans as well as flat entries (`g`), with expandable structured fields. Missing, cyclic or conflicting span parents remain visible as unresolved hierarchy. Top-level fields retain identity by name and duplicate occurrence; array elements use their positions. Supported nested structures are `map[string]any` and `[]any`; unsupported Go types are labeled by type rather than invoking arbitrary formatting methods. Field depth, node count, and value preview limits prevent unbounded expansion; omissions are marked.

The HTTP molecule uses method colors as capability categories and status-code colors as response classes. Extension methods keep their literal labels; unavailable and invalid codes never become successful responses. Pending exchanges remain distinct from completed observations. `Tab` moves between panes, and `Alt+1`, `Alt+2`, `Alt+3` select requests, HTTP details, and related logs. Wide terminals show all three regions; narrow terminals show one region at a time while retaining browsing state. In the standalone HTTP molecule, `Tab` switches list/detail keyboard routing. In details, `1` and `2` expand or collapse request and response sections; `3` toggles parameters independently; `r` switches pretty/raw rendering when captured bytes are available.

`HTTPBody.State` distinguishes `NotCaptured`, `Captured`, `Truncated`, and `Redacted`. A captured zero-byte body is known empty. `ContentType` selects a lexer; if omitted, the molecule uses the corresponding captured `Content-Type` header. JSON, structured `+json`, XML and `+xml`, HTML, CSS, JavaScript, URL-encoded forms, and plain text are supported. Valid JSON opens formatted; malformed or excessively deep JSON retains captured source with a notice. Binary, unsupported-charset, or encoded content shows a byte/encoding summary, with a hexadecimal preview in raw mode. There is no implicit decompression. `HTTPBody.Encoding` describes the submitted bytes, which may differ from wire headers when a caller has decoded them. Pretty/raw views do not mutate captured bytes.

The body preview defaults to `collection.DefaultBodyPreviewBytes` (64 KiB); formatted output is bounded too. Preview truncation is separate from capture-source truncation. Rendering escapes terminal control and formatting characters before applying theme styles. Capture policy, sensitive-data redaction, retained payload size, and source provenance belong to the application; this library neither reads live HTTP body streams nor makes an access or security judgment from a status code.

The native tree, request table, and detail viewport remain exposed. Resize preserves native styles and keymaps. Dataset changes rebuild tree nodes, table rows, and selected detail content; retained stable identities preserve selection and tree expansion. Wrapper keys (`g`, Enter/Space, body section/format controls, and inspector pane/scope controls) take precedence within their documented focus context. Other navigation honors customized native bindings. Configure native styles and keymaps on the exposed models; direct node/content mutations can be replaced by the next data update.

`text.Pending(theme)` uses the compact pending glyph in a fixed five-cell status slot. `text.Pending(theme, frame)` offers a three-position ellipsis with the same allocation; the caller supplies monotonically advancing frames and owns scheduling. Reduced-motion themes retain the static glyph. The HTTP list uses the static default, while selected details spell out “Pending.” Run `text/pending` and press Ctrl+N to inspect the animation frames.

`text.Log`, `text.Trace`, `text.Span`, `text.Upstream`, and `text.Downstream` pair semantic glyphs with escaped caller labels; ASCII profiles use `L`, `T`, `S`, `^`, and `v`. Direction is relative to the caller's service: upstream is a dependency it calls, downstream is a consumer calling it. These atoms do not infer topology from a span's parent or a request/response direction. `text.TimeOfDay` retains milliseconds and the supplied timestamp's location; a missing time stays visibly unavailable. `text.ShortDuration` rounds compact summaries, while HTTP inspection details retain the original duration and full timestamp. The clock abbreviation omits date and zone, so keep full observations accessible across day or location boundaries.

`feedback.Follow` renders the follow/browsing indicator from shared lifecycle atoms: following uses the running glyph and color, and browsing uses `feedback.Paused`. Both modes keep the same allocation. Keyboard actions use `text.KeyHint`, and HTTP section headers use `text.Disclosure`; these atoms have independent catalog specimens.

Folding defaults to enabled. Call `SetFolding(false)` on the HTTP or log-tree molecule, or pass `NoFolds: true` to `pattern.LogInspectorOptions`, to keep all HTTP sections and structured fields expanded without disclosure markers. Collapse/toggle keys are ignored in this mode; grouping and navigation still work. `--no-folds` and saved “No folds” specimens show this setting in the workbench. Enabling folding again starts with the currently expanded content; it does not restore an earlier collapsed layout. Changing folding deliberately reapplies the theme's disclosure glyphs.

`feedback.Scrollbar` is a one-cell vertical atom based on total lines, visible lines and scroll offset. The thumb's size represents the visible fraction; its position is clamped to the actual scroll range. Non-overflowing content retains a blank gutter so arriving data does not shift text. HTTP details and log trees reserve this gutter by default and derive its position from native scroll offsets, including wrapped lines. The default tree scrollbar assumes the wrapper's unframed tree with native help hidden. If you enable native help or add vertical `TreeStyle` padding/borders, supply `LogTree.ScrollbarGeometry` with the total rendered lines, visible viewport lines, native offset and track height for your customization; alternatively disable the scrollbar. The callback receives the current native tree model, and keeps geometry policy with the caller that changed it. Set `ShowScrollbar = false` and resize the molecule to reclaim the column. Request tables retain native scrolling without a scrollbar because their native API does not expose its viewport offset. At a one-cell allocation the scrollbar is omitted to preserve the content cell.

Semantic atoms accept `text.GlyphAndLabel`, `text.GlyphOnly`, or `text.LabelOnly`; the zero presentation uses both. This applies to lifecycle statuses, follow state, observation labels and disclosure atoms. Use `SetSymbols` on a molecule or inspector to refresh its presentation, or set `LogInspectorOptions.Symbols` at construction. IDs and observed HTTP values remain visible regardless of adornment mode. Native tree cursor/fold markers remain structural controls governed separately by folding; HTTP request/response section names also remain visible. Compact pending code cells keep their five-cell glyph slot; details and `text.PendingWithPresentation` honor the selected symbol mode. The original `text.Pending` remains a compact glyph/ellipsis atom.

HTTP details default to a concise summary: `POST /path`, the exact response code and description with elapsed duration, then the timestamp. Labels remain for correlation IDs, where otherwise similar values are ambiguous. Missing optional IDs and timestamps are omitted; unavailable elapsed time and unknown response codes stay explicit. Set `VerboseDetails` to restore labeled summary fields, or `ShowColumnLabels` for HTTP table headings; resize after changing column visibility. `LogInspectorOptions.VerboseDetails` and `ColumnLabels` configure these at construction. Native header padding and borders are measured when allocating and removing a hidden table header.

`text.FormatURL` supports `PathOnly`, `PathAndQuery` (the text helper default), `HostAndPath`, and `FullURL`. Path formats retain escaped path segments; query formats preserve captured ordering and escapes. The path-only form deliberately omits the query; host/path omits scheme and user info; shortened forms omit fragments. Full URL mode displays the captured value without reconstruction. Malformed and opaque targets retain their captured spelling. These are display transformations only: `Selected().URL` and `Entries()` retain the original observation. Use `HTTPLog.SetURLFormat` or `LogInspectorOptions.URLFormat` to choose a built-in form. `SetURLFormatter` supplies an optional caller formatter whose output is escaped as data; it does not alter retained URLs. The formatter is called during rendering refreshes and should be pure and inexpensive.

Workbench flags `--symbols both|glyph|label`, `--url-format path-query|path|host-path|full`, `--verbose-details`, and `--column-labels` expose these choices. The catalog includes symbol-mode, URL-format and labeled-summary variants, plus separate presentation and URL atoms.

HTTP logs also offer a Gantt timeline: set `HTTPLog.Timeline = true` and supply `TimelineNow` as the observation time, or call `TimelineView(now, width, height)` directly. The shared UTC axis spans the retained requests; rows keep ingestion order and keyboard selection. Each bar starts at `HTTPExchange.Time` and stops at `Time + Duration` only when completion and a nonnegative known duration are observed. Pending bars extend to the supplied observation time with an open arrow; a missing or earlier observation time, missing start, or unavailable completion duration stays explicitly unknown. Set `TimelineLegend` to include the endpoint key; it is hidden by default. The native HTTP fixture accepts `--timeline` (and `--legend`). The chart uses terminal-cell resolution, so sub-cell intervals collapse to their endpoint symbol; exact timestamps and durations remain in the selected details. Success, client-error, server-error and pending colors reuse the theme roles, with distinct ASCII endpoints for monochrome terminals. The chart needs at least 36 columns; narrower views show a size hint. The static HTTP log's **Timeline** variant uses overlapping deterministic requests to demonstrate concurrency.

For a compact hierarchy with an in-place focused leaf, call `LogTree.SetDetachedDetails(true)` or set `LogInspectorOptions.DetachedLogDetails`. Each log stays under its trace/span as a single-line summary; the selected summary is replaced at its current position by a full-width focused container containing its message, timestamp and structured fields. Siblings remain before and after it in their original order. Fields are expanded in this section and keep the same ordering, escaping, depth and node limits as inline fields. `D` switches keyboard scrolling between the tree and detail viewport; scrolling the details pauses follow. The native `Details` viewport remains public for styles/key maps; selection changes reset its offset, while updates to the same record preserve it when possible. Resizing keeps the focused container visible with surrounding tree context when space permits; extremely short panes clip its contents. Selecting a trace/span clears the record inspector. Disabling the option restores inline fields, retains the selected record and resets field expansion. The native fixtures accept `--detached-log-details`; the guide offers **Focused leaf** and a **Focused narrow** inspector variant.

Focused leaves use single-line native node geometry by default and measure the native frame offset. For vertically padded or wrapped native nodes, supply `LogTree.FocusedLeafGeometry`: its read-only model snapshot has zero scroll and returns the selected leaf's rendered `[start, end)` row range, plus success. Without a valid override, the component retains the native compact tree view rather than replacing an uncertain row. The callback does not change the source hierarchy.

Timelines accept caller-supplied grouping criteria, for example `requests.SetTimelineGrouping(collection.GroupByService, collection.GroupByEndpoint)`. `HTTPExchange.Service` is an optional caller-provided service name; endpoint grouping reads the captured URL authority without resolving or contacting it. Built-in criteria also include `GroupByHost` and `GroupByPort`. Port grouping normalizes explicit numeric ports and infers 80/443 for absolute HTTP/HTTPS URLs; absent or invalid ports remain unavailable. These are URL destinations, not observations of an actual socket peer. Supply any pure `HTTPGroup` callback to group by application metadata, and compose multiple criteria in order. Group order is first-seen, with ingestion order retained within each group. Keyboard navigation follows the grouped display; source records and selected IDs stay unchanged. Clearing criteria restores the ungrouped order. Short viewports retain the selected request and repeat its group heading when space permits. The native fixture accepts `--timeline --timeline-group-by service,endpoint`; the saved **Timeline grouped** variant shows three services on the same clock.

The correlated inspector offers `InspectorSidebar` (requests beside stacked details/logs), `InspectorTimeline` (full-width timeline above details/logs), `InspectorColumns` (three columns), and `InspectorFocused` (one focused pane). `InspectorAuto` preserves the responsive sidebar default. Pass `Layout`, `TimelineGroups` and the explicit observation `TimelineNow` through `LogInspectorOptions`, then call `SetLayout` to change arrangements without replacing datasets, selected request/log IDs, correlation scope, native styles/key maps, or body modes. Resizing may clamp native scroll offsets. `Layout()` reports the preferred preset and `ActiveLayout()` reports the arrangement that fits: columns and timeline can fall back to sidebar, then to a single focused pane. A focused timeline keeps the timeline request presentation. `L` cycles layouts; `Tab` and `Alt+1/2/3` retain pane navigation. The native fixture accepts `--log-layout timeline --timeline-group-by service,endpoint --detached-log-details`, and the guide saves each layout for comparison.

Request parameters decode URL query strings and complete captured `application/x-www-form-urlencoded` bodies into key/value rows. Repeated values remain separate, empty values are explicit, and malformed encodings show the captured source instead of a partial parse. Form decoding respects the body preview byte limit, charset, encoding and capture state; unsupported or incomplete bodies retain the existing body presentation. Route parameters require application routing knowledge and are not inferred. Disabling folds shows parameters regardless of prior fold state. Body syntax and formatting are visible directly, without a mode caption; capture, truncation and invalid-source notices remain explicit.

HTTP targets default to paths, keeping query values in the independently expandable Parameters section. Explicit `path-query`, `host-path`, `full` or a custom formatter can restore the captured query in the target; the original URL is always retained in observations. HTTP details place parameters and request content beside the response when at least 62 content cells fit, and stack the same sections in narrower panes. The timeline organism gives HTTP details more width while reserving a usable log pane, so its details can use this horizontal arrangement. Resizing preserves folds, selection, raw mode and native viewport customization; scroll offsets can clamp.
