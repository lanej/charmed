# Compose behavior as well as appearance

The service workbench combines an input, table, time-series chart, and details viewport. Its state belongs to one Go model. The browser forwards terminal input to that model.

## Ownership rules

| Owner         | Responsibility                                             |
| ------------- | ---------------------------------------------------------- |
| Theme         | Semantic colors, contrast, ASCII and motion policy         |
| Layout parent | Allocate rectangles in columns and rows, including borders |
| Focus scope   | Route keyboard input to the active child                   |
| Component     | Own its native widget state and return commands            |
| Root runtime  | Own the terminal session and forward commands              |
| Application   | Supply data and handle typed UI events                     |

Tab moves focus. Typing in the filter leaves navigation keys available to the input. Arrow keys change rows when the table is focused. Selection updates the chart and inspector together. Ctrl+N advances background samples even while another region is focused.

The split layout becomes stacked on small terminals. The selected service persists across resize; hidden regions leave the focus order.

## Dependencies follow capabilities

The deployment comparison follows the same ownership rules. The parent coordinates selection and data; each metric uses `chart.ComparisonPanel`, which composes `chart.DistributionComparison`, `chart.IntervalBand`, and `chart.TimeSeries`. `feedback.Attention` composes `text.Pill`. Optional rules are evaluated by `attention` and `cohort.Assess`, independently of those renderers.

Explore [cohort distributions](#chart/distributions), [attention](#feedback/attention), and the [deployment example](#deployment) as separate catalog entries. The same components render the full screen.

Import `input`, `chart`, `layout`, or `form`. Atomic levels organize the catalog; they do not force package names or artificial composition layers. The Go library has no JavaScript runtime dependency.

## Find a story by composition level

Native fixture factories and their registrations live together in level-specific files. The registry joins them into one catalog; the generator places each MDX page under its level and capability. Story IDs remain stable as files move.

| Level | Native fixtures and registrations | Example generated MDX |
| --- | --- | --- |
| Foundations | `story/foundations.go` | `docs/generated/foundations/foundations/theme.mdx` |
| Atoms | `story/atoms.go`, `story/atoms_charts.go` | `docs/generated/atoms/chart/interval-band.mdx` |
| Molecules | `story/molecules.go` | `docs/generated/molecules/chart/delta.mdx` |
| Organisms | `story/organisms.go` | `docs/generated/organisms/chart/comparison-panel.mdx` |
| Screens | `story/screens.go` | `docs/generated/screens/screen/deployment.mdx` |

The same `Composes` declarations generate **Composed from** links and reverse **Used by** links. Follow the [deployment screen](#screen/deployment) to its [comparison panel](#chart/comparison-panel), then its [distribution comparison](#chart/distributions) and [interval-band atom](#chart/interval-band).

The generator rejects broken links, duplicate entries, cycles and dependencies on a higher atomic level. Same-level composition is allowed. These checks validate the declared catalog relationships; Go package boundaries remain responsible for code dependencies. Shared scene adapters and deterministic sample data stay in `story/scene.go` and `story/samples.go`. Data analysis and optional attention policies stay in `cohort` and `attention`.

Add a template level when a reusable screen arrangement needs its own example. Empty levels do not require placeholder fixtures.
