Brand sheet

Charmed is a terminal-first design system. Its identity should feel like the interfaces it creates: precise, compact, and legible. Brand color stays restrained; semantic colors in terminal fixtures carry the meaning.

Use the identity

The primary lockup pairs a compact prompt mark (>_) with the lowercase charmed wordmark. Keep the mark and name together for the website, documentation, and repository art. The small prompt mark can stand alone when the surrounding product name is visible.

Do not use the mark as a generic status badge or replace a status label with brand green. Preserve legibility on both light and dark backgrounds; the default documentation identity is dark.

Tokens and roles

The swatches below are derived directly from Charmed's native dark theme. The generated CSS and this page are populated from the same semantic roles used in terminal fixtures, including surfaces, borders, labels, and series colors. Syntax highlighting maps to semantic roles rather than introducing a parallel set of hex values.

For native widgets, source semantic colors from theme.New(theme.Dark). Documentation consumes these values during static generation; it does not define an independent palette. Success, information, warning, danger, and data-series colors remain distinct.

Typography and code

Use system sans-serif for documentation and labels. Use bundled JuliaMono for terminal snapshots, source listings, and short inline references. Source examples should use lexical highlighting, while terminal snapshots should retain the ANSI colors emitted by the native fixtures.

Composition

Lead with the terminal output. Show alternate states in adjacent variant tabs and a small runnable usage example immediately afterward. Link to the complete fixture implementation separately; don't present an entire fixture lifecycle as the simplest way to call an atom. The brand should support the component content rather than compete with it.
