Component reference

Browse Atoms, Molecules and Organisms, then choose a capability group. Each group has its own page with native previews, variant tabs and Go examples. Components link to their dependencies across categories.

The JSON viewer supports syntax-highlighted, foldable objects and arrays. Its usage and lifecycle guide covers native viewport customization, source fidelity and bounded parsing. The correlated inspector composes it into both HTTP payload panes.

The contracts below describe sizing, state and native customization across the catalog.

Time-series traces use native braille dots for finer terminal resolution. Shared axes and series colors retain their meaning; ASCII mode keeps its numeric fallback.

Molecules keep related information together within the child's cell allocation. A labeled field wraps help or validation feedback to its native input width; resize through field.Input.Resize(columns). Metric trends keep the current value and unit visible in short allocations. An empty value is unavailable, while empty history does not discard a known current value. Distribution labels and metadata wrap at the supplied width; allow room for their resulting rows.

Legends are opt-in. Set DistributionComparison.ShowLegend, compose BandOptions.Legend or chart.SeriesLegend, or use chart.PanelOptions{ShowLegend: true} with chart.Panel. Allocate its child with options.PlotSize(size, series, palette) so wrapped keys get their actual number of rows. chart.PanelPlotSize remains available for single-row legacy allocations. Legend symbols reuse their plotted styles; label custom boundary markers with BandMarker.Label. Native fixtures accept --legend, and relevant saved variants include With legend. Rendering a panel preserves the native child's state and custom styles; callers own its resize lifecycle.

Text inputs distinguish disabled state with an inactivity shade and a slashed-circle default prompt (ASCII /). Disabling suppresses wrapper focus, editing and the native real cursor; re-enabling retains the underlying native model state. A custom native prompt remains caller-owned. Text.View applies disabled presentation to a copy, while SetTheme reapplies shared styles. Resize reserves the actual prompt width and the native cursor cell. Textarea active lines, line numbers and selection use theme surfaces and colors. Validation messages belong to input.Field.

Saved text, textarea and field fixtures explicitly prepare static focus with cursor blinking disabled. They do not call general scene initialization or execute commands; native interactive runs retain their normal focus and clock lifecycle. Percentage bars keep tiny nonzero values in scientific notation instead of labeling them as zero. When a label cannot fit, a truncation mark signals that limit.

diagram.StateDiagram renders explicit States, Transitions and an optional Active state ID. State has an ID, an optional display label and Initial/Final flags and an optional Outcome (OutcomeNone, OutcomeSuccess or OutcomeError); Transition has From, To and an optional label. View(width, palette) prefers a horizontal layout with labeled arrows directly between adjacent boxes, and switches to a vertical layout when the horizontal graph is too wide. Self-loops sit beside their state; longer edges carry labels on their own paths. Initial states use rounded borders, ordinary states use square borders, and final states use double borders; ASCII uses parentheses and equals-sign borders for the same distinction. Possible states use dim semantic colors (DimForeground, DimSuccess and DimDanger). The active state uses the corresponding bright color (Accent, Success or Danger), bold text and a heavier border; final states retain double borders. Success and error outcomes have explicit text markers and remain independent of Final. Nodes and arrows retain the same meaning across themes and ASCII output, with no diagram legend. State and transition declaration order keep placement deterministic; parallel transitions, cycles and self-loops remain separate. The complete graph is returned or an error reports the minimum width across both layouts. Height depends on the selected orientation; callers must allocate enough rows or use a viewport. Labels are single-line plain text; wide and combining characters retain cell alignment. Empty graphs render an empty string. Unknown endpoints, duplicate IDs, multiple initial states, unknown active states and outgoing transitions from final states and invalid outcomes return errors. The component displays application state; applications own transition execution.

Transition tracing is opt-in through Trace: diagram.TransitionTrace{Steps: []int{0, 1}, Last: 1}. Steps contains indices into Transitions in chronological order, so parallel edges and repeated loops identify the exact path. Last: 0 defaults to the most recent transition, positive Last shows that many recent steps, and All: true shows the whole path. An empty trace highlights no history. The newest edge and its label use the accent color and a heavier stroke; earlier visible edges and visited states use normal semantic colors, while possible paths stay dim. The active state keeps its bold emphasis. In monochrome, the newest route uses heavier ASCII strokes. Repeated edges are highlighted once; highlighting does not show traversal counts or chronological order. History must reference existing transitions, form a continuous path and end at Active when supplied; invalid history returns an error, including invalid steps outside the displayed window. Negative Last and combining All with positive Last are errors. Tracing does not change graph geometry or mutate caller history. In the guide, Left/Right replays a path and H cycles between the last transition, last three and whole path.

Connection states#

Connection atoms render feedback.Connected and feedback.Disconnected with the shared bright, normal or dim emphasis. Connection state comes from the application; disconnected is inactive rather than a warning, and unknown remains a separate state. Compose either atom into layout.Footer.Status or another region.

Application chrome#

Tabs select an application section. Left/Right wrap around; Home/End select the first/last item. Only a focused tab bar handles these keys; Tab and Shift+Tab remain available to the parent's focus scope. Return the command from Tabs.Update to receive interaction.Selected{Component: "tabs", ID: ...} when keyboard selection changes. Select and SetItems update state without emitting commands. IDs must be unique and stable. SetItems copies the item slice, retains the selected ID where possible and otherwise selects the first item; resize retains selection, focus and theme. The exported Theme can be customized directly and is never rebuilt. Shared focus and selection styles identify the active tab, with reverse video in monochrome; narrow bars show < and > for hidden neighbors and keep the selected tab in view. Very small widths clip the active label.

Header places a title on the left and actions on the right, with a second context row when Context is nonempty. Reserve one row without context or two with context. Actions disappear if they cannot fit beside the full title; the title clips only when it exceeds the allocation. Action strings are display content: the application owns their bindings and effects.

Footer places help on the left and status on the right in one row. Status disappears when both cannot fit, then help clips to the allocation. Both fields accept styled text, including native help output. Header and footer fields use only their first line; these two components do not wrap. Widths are terminal cells, including wide Unicode labels and ANSI styling; nonpositive widths render nothing.

Identity header promotes a request UUID or another entity ID to the headline. Kind, ID and optional Context are escaped data; optional Actions accepts styled display text. The kind moves above the identifier when needed, then the identifier wraps without abbreviation. Reserve lipgloss.Height(header.View(width, palette)) rows before allocating content. Actions appear only when they fit beside a single-line headline.

Foldable section composes a panel and a disclosure marker. Set Collapsed to render only the heading, and use Height(expandedHeight) when returning space to siblings. NoFolds shows all content without disclosure markers. Title and Content accept styled text; state, keys and focus belong to the caller.

See the application shell for these components composed around an active content panel. Sidebar navigation, breadcrumbs and toolbars remain separate future patterns.

Log levels#

Log level atoms render feedback.TraceLevel and native log.DebugLevel, InfoLevel, WarnLevel, ErrorLevel and FatalLevel with feedback.LogLevel(level, text.Normal, palette). TRACE uses subdued neutral, DEBUG cyan, INFO blue, WARN amber, ERROR red and FATAL magenta. Severity sets the semantic tone; bright, normal and dim emphasis remain independent. The six labels reserve equal cell widths, including in ASCII/monochrome output. Theme fields Trace, Debug, Fatal and their Dim counterparts allow customization. feedback.TraceLevel is a typed log.Level(-8) extension for display and collection.LogEntry; Charm Log’s native String and ParseLevel do not recognize it. Other unknown values display LEVEL n neutrally, preserving the value rather than claiming a known severity. Rendering FATAL performs no logging or exit. collection.LogViewer composes the atom between its timestamp and message, retaining Charm Log’s structured-field formatting, bounded history and scroll behavior.

Selection and action atoms#

Checkbox, radio, toggle and button are concrete Bubble Tea models with Update(msg) (Model, tea.Cmd) and View() string. Constructors accept a stable application ID, plain-text label and theme; checkbox also accepts input.Unchecked, Checked or Mixed, while radio and toggle accept their initial boolean selection. The embedded input.Control exposes native Keys key.Binding, theme, disabled state and reason, plus Focus, Blur and Focused. Parents route messages and own traversal; controls handle Space/Enter only while focused and available. A nonempty DisabledReason disables activation and remains visible alongside an explicit disabled label. Labels and reasons are escaped before terminal rendering. Focus reserves the same horizontal inset, and changing selection does not change mark widths.

Checkbox activation changes unchecked or mixed to checked, and checked to unchecked; invalid states render [?] and cannot activate. Checkbox emits input.CheckChanged{ID, State}; radio emits input.RadioSelected{ID} only on a new selection; toggle emits input.Toggled{ID, On}. Retain the returned model and return its command to Bubble Tea. Radio parents own group membership and deselect siblings after receiving a selection. Button emits input.Activated{ID} without executing an operation or guessing its outcome. The parent sets Busy during outstanding work, handles success or failure and clears it. Busy buttons show [BUSY] and suppress activation; disabled buttons retain their explanation. Theme and binding changes remain caller-owned across updates.

Data and evidence atoms#

Value state uses text.ValueState with a present zero value and explicit missing, redacted and invalid states. state.View(value, emphasis, palette) renders present text, including "" for a present empty string, and never displays supplied content for a non-present state. Zero and false stay present. Unknown enum values render an explicit unknown state. This is presentation metadata; callers retain the original observation and decide which state applies.

Freshness keeps ObservedAt, StaleAfter and Emphasis; View(now, palette) receives its clock explicitly. An age equal to the positive stale threshold is stale; a nonpositive threshold disables stale classification. Missing observation/clock and future timestamps remain explicit. Freshness is independent of health and severity and never schedules ticks. The application owns refresh cadence and stale policy.

Quantity keeps a numeric observation, ValueState, literal unit, precision, scale, emphasis and minimum right-aligned cell width. Scaling is opt-in through text.DecimalScale or BinaryScale; the zero scale is unscaled. Counts, bytes and rates share the same formatting without inferring units. Precision is clamped to 0–9 decimal places, ordinary rounding follows Go's float formatting, and tiny nonzero observations use scientific notation rather than appearing to be zero. Non-finite values are invalid. Formatting never changes the observation, and a value wider than its alignment width remains complete on one line.

Identifier stores the full Value and returns a middle abbreviation through Label(width) or View(width, palette). Width is in terminal cells; both ends are retained when space permits, with portable dots marking omission. Nonpositive widths render nothing. An empty identity displays unavailable when space allows. Use Value for identity, inspection and actions; an abbreviated label is not unique and must never become an identity key.

Match highlighting accepts source text, half-open text.MatchRange{Start, End} rune offsets and native normal/matched Lip Gloss styles. Matching policy stays with the caller; rendering combines overlapping ranges, clips out-of-range portions, ignores reversed ranges and highlights an entire grapheme when any of its runes match. Source controls are escaped before rendering. The command palette uses this atom with the same escaped-text offsets as its native fuzzy matcher; selection, disabled styling and search results retain their existing behavior.

Sort indicators distinguish SortNone, SortAscending and SortDescending, optionally labeling positive one-based priority. They render ordering supplied by the caller and never sort records. Change markers distinguish Unchanged, Added, Modified and Removed with symbols and labels as well as semantic color. They do not infer whether a numerical change is beneficial.

Omission markers distinguish DisplayHidden from SourceTruncated; KnownCount separates an exact omitted item count from an unknown count. A known zero renders nothing, while negative known counts render an invalid-count label. Display omission means more content exists outside the current presentation; source truncation means the captured observation itself is incomplete. The marker performs no truncation or retrieval.

Operation outcomes render feedback.Succeeded, Failed, Canceled, TimedOut and the zero-value OutcomeUnknown. These are reported results; pending and running remain lifecycle states. Cancellation and timeout do not establish rollback or absence of external effects. Applications own execution, cancellation, reconciliation and final classification; atoms only present the supplied result. All semantic labels survive monochrome output, independently of bright, normal and dim emphasis.
